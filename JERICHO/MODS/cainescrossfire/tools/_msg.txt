cainescrossfire: the arena editor culls and caches its background (it was laggy)

Panning or dragging re-rasterised the WHOLE level map on every redraw: the
background only knew how to .resize() the entire image to the map's on-screen
size and hand that to ImageTk.PhotoImage each time - ~37 ms per redraw for a
modest 2000x2000 map, several times a frame while the mouse moved. Worse, when
the map's on-screen size went over the old 40M-pixel guard the map was silently
not drawn at all, which is what happened when zoomed in on a big city rip.

Now:
- _draw_bg crops to the part of the map actually on screen and scales only that,
  so every frame is canvas-sized no matter how big the map or how far out you
  are (proper culling, not a "skip it if it is too big" guard).
- the resulting tile is CACHED by (source, crop box, target size), so a redraw
  that did not move the view costs nothing.
- pan/drag/Configure coalesce through _redraw_soon() (after_idle), so a burst of
  motion events becomes one redraw instead of one per event.
- spawns and pickups are culled to the visible rect while drawing.
- label text is only reconfigured when it actually changes.

Measured: pan + redraw with a map about the view's size is now 1.0 ms/frame
(was ~37 ms just for the background), and a map far bigger than the view draws
instead of vanishing.

--uitest now guards this: it builds a 2000x2000 test map, pans and redraws 25
times asserting under 100 ms/frame, checks a huge map still draws, and checks
the tile cache is reused.
